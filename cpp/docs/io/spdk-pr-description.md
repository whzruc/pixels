# SPDK NVMe Backend — Pull Request Description

## Summary

This PR adds an optional SPDK user-space NVMe backend for the Pixels C++ reader.
The existing io_uring and POSIX paths remain available; SPDK is selected at
runtime with `localfs.enable.spdk=true` and requires a binary built with
`-DPIXELS_ENABLE_SPDK=ON`.

## What changed

- Added process-wide SPDK NVMe controller discovery and file-to-LBA-map lookup.
- Added VFIO/LBA-map test tooling for detaching NVMe devices from the kernel
  driver and restoring them after a run.
- Added thread-local SPDK I/O qpairs and asynchronous submit/complete handling.
- Added `SpdkBufferPool` backed by `spdk_dma_malloc`, including single- and
  double-buffer modes.
- Added DMA-aware `ByteBuffer` ownership and cleanup.
- Connected SPDK through `LocalFS`, `PhysicalLocalReader`,
  `PixelsRecordReaderImpl`, and the DuckDB scan binding.
- Added explicit file-list binding for SPDK runs, avoiding filesystem glob/stat
  calls after VFIO detaches the data disks.
- Added SPDK build targets and the existing performance-suite integration.

## Configuration and prerequisites

```text
localfs.enable.spdk=true
localfs.async.lib=spdk
pixel.bufferpool.mode=legacy
```

The host must provide SPDK/DPDK libraries, hugepages, VFIO-bound NVMe devices,
and an LBA map generated by `testcase/spdk/gen_lba_map.py`.

## Correctness smoke test

The 24-SSD Q24 correctness run completed for 12, 24, and 48 worker threads in
both `spdk` and `spdk-doublebuffer` modes. All runs reported:

```text
submitted = completed
errors = 0
```

## Representative performance result

Q24, 24 SSDs, measured with `EXPLAIN ANALYZE` (seconds):

| Threads | SPDK | SPDK double-buffer |
|---:|---:|---:|
| 12 | 142.81 | 117.09 |
| 24 | 72.92 | 62.54 |
| 48 | 50.46 | 45.61 |

At 48 threads, double buffering reduced wall time by approximately 9.6% in
this run. The corresponding SPDK I/O throughput was approximately 36.7 GB/s
for single-buffer mode and 40.6 GB/s for double-buffer mode, with zero recorded
I/O errors.

Raw benchmark logs, perf data, flame graphs, core dumps, and generated result
directories are intentionally excluded from this PR.

## Limitations

- SPDK mode requires exclusive VFIO ownership of the NVMe devices.
- The LBA map must match the exact mounted dataset and device topology.
- The benchmark numbers are host-specific and are included only as a
  representative correctness/performance check.
